# WoSoCenter v6.0 — نسخهٔ آمادهٔ انتشار در GitHub Pages

این نسخه از فایل کامل اصلی تهیه شده، سه فایل آپدیت با آن تطبیق داده شده‌اند، و یک گردش‌کار مستقل برای انتشار **سایت استاتیک بدون Jekyll یا npm** اضافه شده است.

## روش پیشنهادی استقرار

1. محتویات **ZIP کامل** را استخراج کنید. پوشه‌ها و فایل‌ها، مخصوصاً `assets/`، `data/`، `.nojekyll` و `.github/workflows/deploy-pages.yml` باید **مستقیماً در ریشهٔ مخزن** باشند؛ فایل ZIP را به عنوان یک فایل منفرد در GitHub آپلود نکنید.
2. فایل‌ها را در شاخهٔ پیش‌فرض پروژه (`main` یا نام شاخهٔ پیش‌فرض خودتان) Commit/Push کنید. اگر نسخهٔ کامل از قبل موجود است، می‌توانید صرفاً محتویات ZIP آپدیت کوچک را روی فایل‌های فعلی جایگزین کنید.
3. در GitHub وارد **Settings → Pages → Build and deployment → Source** شوید و **GitHub Actions** را انتخاب کنید. این تغییر تنظیمات لازم است؛ صرفِ اضافه‌شدن فایل workflow، روش فعلی انتشار را عوض نمی‌کند.
4. در بخش **Actions**، گردش‌کار **Deploy WoSoCenter (static Pages)** را باز کنید. اگر پس از Push خودکار شروع نشد، از گزینهٔ **Run workflow** روی شاخهٔ پیش‌فرض استفاده کنید.
5. ابتدا مرحلهٔ **Validate files and package static site** و سپس مرحلهٔ **Deploy validated static site** باید سبز شوند. در پایان آدرس وب‌سایت از بخش Settings → Pages قابل مشاهده است.

## اگر هنوز خطای ۱۰ دقیقه‌ای می‌بینید

- اگر عنوان گردش‌کار همچنان **pages build and deployment / deploy (dynamic)** باشد، احتمالاً هنوز در حال استفاده از فرایند انتشار داخلی GitHub هستید، نه گردش‌کار جدید **Deploy WoSoCenter (static Pages)**. مرحلهٔ ۳ را بررسی کنید.
- اگر مرحلهٔ اعتبارسنجی خطا می‌دهد، معمولاً فایلی از ZIP اصلی یا پوشه‌های منابع ناقص بارگذاری شده است؛ پیام دقیق خطا نام فایل را می‌گوید.
- اگر اعتبارسنجی موفق است اما مرحلهٔ Deploy همچنان پس از ۱۰ دقیقه بدون خطای ساخت فایل‌ها متوقف می‌شود، وضعیت سرویس GitHub Pages، محدودیت‌های محیط `github-pages` در Settings → Environments و ثبت‌های deployment در Actions را بررسی کنید. در صورت گیرکردن سابقهٔ انتشار، یک بار Source را تغییر داده و مجدداً روی GitHub Actions بگذارید. این نوع مشکل لزوماً در کد وب‌سایت نیست.
- برای تشخیص **قطعی علت خطای مخزن خودتان**، متن کامل لاگ **Actions → اجرای ناموفق → deploy → خطا** لازم است. هیچ بستهٔ کدی نمی‌تواند اختلال سمت سرور GitHub Pages را تضمینی رفع کند.

## موارد تست‌شده

- بررسی تطابق و کامل‌بودن فایل‌ها، ارجاعات HTML/CSS/JSON و وجود دارایی‌ها.
- بررسی Syntax فایل‌های JavaScript با Node.js.
- تست هر ۳۱ آرایش، تعداد یازده بازیکن، جلوگیری از بیرون‌زدن یا روی‌هم‌افتادن کادر کارت‌ها، ثابت‌ماندن دروازه‌بان، و پیش‌نمایش وکتوری برای هر آرایش.
- حفظ کد اصلی برنامهٔ مسابقات (`fixture.html` / `app.js`) و تمام تصاویر و فونت‌های سایت.

**توجه:** در این بسته هیچ تغییری در منطق اصلی کارت‌ها و آرایش‌ها داده نشده است؛ فقط نسخهٔ لینک فایل‌های CSS و JS در `lineup.html` برای نوسازی Cache مرورگر تغییر کرده است. فایل‌های `scripts/` و `tests/` فقط برای بررسی قبل از انتشارند و جزو وب‌سایت خروجی قرار نمی‌گیرند.
